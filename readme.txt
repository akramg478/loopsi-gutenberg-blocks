Advanced Gutenberg query blocks for displaying WordPress content with flexible layouts and filtering.

== Description ==

Loopsi - Blocks provides a dynamic posts query block for the block editor. Build custom post grids with taxonomy filters, meta queries, pagination, load more, infinite scroll, and display toggles.

**Features**

* Query any public post type
* Taxonomy filters with checkbox term selection
* Meta query builder
* Grid or list layout with 1–6 columns
* Pagination, load more, or infinite scroll
* Show/hide title, thumbnail, excerpt, author, and read more link
* Optional render caching with automatic invalidation on content changes

== Installation ==

**For site owners (installing a release ZIP):**

1. Upload and activate the plugin through the WordPress Plugins screen.
2. No npm or Node.js is required on the server.

**For developers (working from source):**

1. In `wp-content/plugins`, clone the repository as `loopsi-blocks`: `git clone https://github.com/akramg478/loopsi-gutenberg-blocks.git loopsi-blocks`.
2. Run `composer install --no-dev` in the plugin directory.
3. Run `npm install && npm run build` to compile block assets.
4. Activate the plugin in WordPress.

To create a distribution ZIP (includes the readable `src` directory, and excludes `node_modules`):

`npm run build && npm run plugin-zip`

== Source code ==

`build/index.js`, `build/index.css`, `build/index-rtl.css`, `build/style-index.css`, and `build/style-index-rtl.css` are generated by `@wordpress/scripts`, which uses webpack. The right-to-left stylesheets are generated from the same source stylesheets. The human-readable source for those files is included in this plugin, in the `src` directory.

* `src/index.js` registers the block.
* `src/blocks/posts-query/edit.js` is the block editor script compiled into `build/index.js`.
* `src/blocks/posts-query/editor.scss` is compiled into `build/index.css`.
* `src/blocks/posts-query/style.scss` is compiled into `build/style-index.css`.

To regenerate the files in `build` from that source:

1. Install Node.js.
2. In the plugin directory, run `npm install`.
3. Run `npm run build`.

The `node_modules` directory is created only on the machine where you build. Do not include it in the plugin zip.

== Frequently Asked Questions ==

= Why is node_modules so large? =

The `node_modules` directory is a local build dependency only (often 300MB+). It must not be uploaded to WordPress.org or production sites. The readable block source in `src` is included in the release package. Use `npm run plugin-zip` to generate that package.

= Why do I need to run Composer and npm? =

Only when developing from source. End users installing the release ZIP do not need Composer or npm.

= Why is my load more button not showing? =

Ensure you have more published posts than the selected "Posts Per Page" value.
